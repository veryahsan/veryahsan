**Layers I work across**

- **Runtime & framework** — Ruby 3.x, Rails 8, Puma, Bootsnap
- **Data** — PostgreSQL with JSONB, indexes, query plans, migrations
- **Caching & pub/sub (Redis)** — Rails low-level + fragment caching on `:redis_cache_store`, Russian-doll caching, key/version-based invalidation, ActionCable Redis adapter for pub/sub fan-out, Redis-backed session store, rate limiting via `rack-attack`, distributed locks for idempotent jobs
- **Background & realtime** — Sidekiq with multi-queue setups (Redis-backed), ActiveJob, ActionCable + Turbo Streams broadcasts, ActionMailer
- **Frontend (server-rendered)** — Hotwire (Turbo + Stimulus), Tailwind CSS, Importmap, ActiveStorage + libvips
- **Auth & RBAC** — Devise (`:confirmable`), OmniAuth (Google + GitHub), multi-provider identity linking, Pundit policies
- **API surface** — JSON:API via `jsonapi-serializer`, JWT-authenticated `/api/v1`, `rack-cors`
- **Encryption & secrets** — Lockbox column encryption, Rails encrypted credentials, dotenv
- **Observability & audit** — Sentry, Lograge, Ahoy, Audited
- **Admin** — ActiveAdmin, protected Sidekiq dashboard

<!--  PATTERNS                                                     -->
<!-- ============================================================ -->

<img src="https://readme-typing-svg.demolab.com?font=Fira+Code&weight=600&size=22&duration=1&pause=99999&repeat=false&color=CC0000&center=false&vCenter=true&width=560&height=40&lines=%23+Patterns+%26+concepts+I+work+with" alt="# Patterns & concepts I work with" />

- **Multi-tenant SaaS** modeling: organisation-as-tenant, role-based membership, manager hierarchies, scoped queries
- **Clean separation of concerns** — thin controllers, business logic in well-named objects, presentation logic out of models, authorization in dedicated policy classes
- **ActiveRecord at depth** — polymorphic and many-to-many associations, soft-deletes, self-referential graphs, JSONB columns
- **Authentication & SSO** with Devise + OmniAuth (Google, GitHub) and a multi-provider identity-linking pattern, plus deny-by-default RBAC with Pundit
- **JWT-authenticated APIs** alongside session-based web auth, with the same authorization rules guarding both surfaces
- **Encrypted-at-rest credentials** for third-party integrations (Lockbox)
- **Caching strategies** — fragment / Russian-doll caching with stable cache keys, low-level `Rails.cache.fetch` for expensive reads, HTTP / ETag conditional GETs, cache-aside reads with explicit invalidation
- **Pub/sub & realtime** — Redis as the message broker behind ActionCable; Turbo Streams broadcast model and job changes to subscribed channels for live UI updates without polling
- **Background-first integrations** — webhooks land in a controller, hand off to Sidekiq, and broadcast results back to the UI via Turbo Streams over ActionCable

On the Rails side I lean on **Hotwire** (Turbo Frames, Turbo Streams, Stimulus controllers) with **Tailwind** and **Importmap** so the monolith ships interactive UI without a separate build pipeline.

When a true SPA is the right call I reach for **React** (~2 years of production experience). Concepts I work with:

- **Components & composition** — functional components, composition over inheritance, lifting state up, container vs presentational split, compound components, render props / children-as-function patterns
- **Hooks (built-in)** — `useState`, `useEffect`, `useRef`, `useMemo`, `useCallback`, `useReducer`, `useContext`, `useLayoutEffect`, `useId`
- **Custom hooks** — extracting reusable behaviour (`useDebounce`, `useFetch`, `useLocalStorage`, etc.) and keeping components declarative
- **State management** — local state, **Context API** for cross-cutting concerns, **Redux Toolkit** (slices, RTK Query) for larger apps
- **Routing** — React Router (nested routes, loaders, protected routes, route guards)
- **Data fetching** — `fetch` / `axios` with JWT, **React Query / SWR** for caching + invalidation, optimistic updates, suspense-based loading
- **Forms** — controlled vs uncontrolled inputs, **React Hook Form** + schema validation (Zod / Yup)
- **TypeScript with React** — typed props & events, generics, discriminated unions for variant components, strict tsconfig
- **Performance** — `React.memo`, `useMemo`, `useCallback`, key-stable lists, code-splitting with `React.lazy` + `Suspense`, virtualization for long lists
- **Styling & motion** — **Tailwind CSS**, CSS Modules, **Framer Motion** for declarative animations
- **Testing** — **React Testing Library** with Jest / Vitest, user-event interactions, mocking fetch with MSW
- **Tooling & build** — Vite, ESLint, Prettier, environment-based config
- **Integration with Rails** — consuming Rails JSON:API endpoints with **JWT** auth, error normalisation, pagination cursors, file upload with ActiveStorage direct uploads

I'm also comfortable bridging the two worlds — a Hotwire-first Rails app that mounts React islands for genuinely interactive surfaces, sharing the same JSON:API and auth tokens.
